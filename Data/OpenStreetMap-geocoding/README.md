# OpenStreetMap island-name lookup — Samothrace area

Answers a direct follow-up to `Data/naturalEarth/README.md`'s own "real
gap" section: Natural Earth has no name for Samothrace, or for most
individual Aegean islands its own size — but Samothrace (~178 km²) is
well above Natural Earth's "minor island" size tier, so is it possible
that *non-minor* islands are named somewhere else in the data? Checked
directly (`ne_10m_admin_0_countries`, `ne_10m_admin_0_map_subunits`,
`ne_10m_admin_1_states_provinces`) — no, Natural Earth genuinely has no
per-island names at this scale, political or physical. This directory
is the answer to the natural next question: **what does, and what does
it take to get at it.**

Generated by `fetch_island_names.py` (run it again any time; see
"Re-running" below) into:

- `osm_island_names.geojson` — one Point feature per qualifying island,
  with `name`, `name_source`, `area_km2`, and OSM provenance fields.
- `metadata.json` — this layer's display metadata (color, group, draw
  order, which properties to show), read directly by
  `desk_hmsvc/natural-earth-map/service.py` (see "Integration" below).

## What "not much smaller than Samothrace" means here

Every landmass from `Data/naturalEarth/ne_10m_land.geojson` +
`ne_10m_minor_islands.geojson` with a computed area **≥ 50% of
Samothrace's own** (≥ ~92 km², `MIN_AREA_FRACTION_OF_SAMOTHRACE` in the
script) — a defensible, one-line-adjustable reading of "not much
smaller," not a fixed list. 37 landmasses qualify as of this writing,
Samothrace itself included.

## Why this enumerates from Natural Earth, not from OpenStreetMap

The obvious tool for "find every OSM feature tagged `place=island` in a
bounding box" is the **Overpass API** — but every Overpass endpoint
tried was unreachable or actively rejected requests from this
environment: `overpass-api.de` directly (alternating `406`/timeout),
and five public mirrors (`kumi.systems`, `private.coffee`,
`monicz.dev`, `openstreetmap.fr`, `openstreetmap.ru`, `nchc.org.tw` —
`500`s, timeouts, or a redirect to another failing mirror). Likely an
IP-range block on this environment's egress, not a real Overpass outage
— worth retrying from a different network if Overpass access matters
later.

**[Nominatim](https://nominatim.openstreetmap.org)** (OSM's own
geocoding service) *is* reachable — but it has no "enumerate everything
of type X in a box" endpoint, only forward search (by name) and reverse
geocoding (by point). So the enumeration step here uses Natural Earth's
own already-vetted land/minor-islands polygons instead — arguably more
robust than an Overpass-based enumeration would have been anyway, since
it can't miss an island because an OSM mapper forgot to tag
`place=island` on it. OpenStreetMap's only job in this pipeline is the
one thing Natural Earth genuinely can't do: supply each landmass's
*name*.

## Method

1. **Decompose** every polygon *part* of Natural Earth's land +
   minor-islands layers (a `MultiPolygon`'s each element is one
   contiguous landmass) and compute each part's area via a local
   equirectangular-projected shoelace formula — not survey-grade, but
   it reproduced Samothrace's real-world area (~178 km²) as 184.1 km²
   (within 4%), which the script checks directly as its own
   calibration step.
2. **Drop mainland.** Any part whose bounding box touches the regional
   bbox's own edge (`Data/naturalEarth/README.md`'s bounding box) is
   treated as clipped mainland Europe/Anatolia/Africa, not a real
   island — confirmed directly: the biggest excluded parts are
   ~956,000 km² and ~377,000 km², obviously continents.
3. **Threshold** against Samothrace's own computed area (see above).
4. **Name each one**, via Nominatim, in priority order — each tier only
   tried if the previous one failed, and the result's own `name_source`
   property records which tier actually won (this project's established
   convention for not collapsing different confidence levels into one
   undifferentiated field — see `cartography.md`'s own writeup on
   elevation-label provenance for the same idea applied to a different
   pipeline):

   | `name_source` | What it means |
   |---|---|
   | `osm_search_seed_island` | A hand-supplied candidate name (`SEED_NAMES` in the script — general geography knowledge, used only as a search *query*, never as the output itself) matched a real `category=place`, `type` in (island, islet) OSM record near this landmass. The strong case — 30 of 37. |
   | `osm_search_seed_administrative` | Same seed, but the only real match was a `boundary`/`administrative` record (a country or region), not a `place=island`/`islet` tag. Real finding, not a guess: **Cyprus is the clearest example** — searched directly, OSM's only record actually named "Cyprus" is its own country-administrative boundary; there is no separate island tag for it at all. |
   | `osm_search_admin_derived_island` / `..._administrative` | Same two outcomes, but the query came from this landmass's own reverse-geocoded administrative name instead of a hand-supplied seed — covers a landmass `SEED_NAMES` has no entry for, or whose seed was simply wrong. This tier is what actually resolved several landmasses during development after a hand-guessed seed named the *wrong nearby island* (see "A real mix-up, caught and fixed" below). |
   | `osm_administrative_fallback` | Neither search tier found anything. Falls back to whatever administrative unit Nominatim's plain reverse-geocode returns, flagged as administrative rather than the island's own name — usually still correct for a single-island municipality, but **not guaranteed**, and the flag says so rather than silently asserting it. Only 1 of 37 (Paros) landed here. |
   | `unresolved` | Reverse geocoding itself returned nothing. Kept with `name: null` rather than dropped — a silent drop would misrepresent "OSM lookup failed" as "no large island here." Did not occur in this run. |

   37/37 resolved in the current output: 30 `..._island`-tier (direct
   or admin-derived), 5 more `..._island` via the admin-derived path, 2
   `..._administrative`, 1 `osm_administrative_fallback`.

### A real mix-up, caught and fixed

The hand-supplied `SEED_NAMES` are informal, general-knowledge guesses
at each landmass's common name — entered *before* confirming anything
against OSM, matched to a landmass purely by eyeballing coordinates.
Two came out wrong during development: the landmass near `(43.18,
16.57)` was guessed "Korčula," and the one near `(42.95, 16.91)` was
guessed "Mljet" — actually Hvar and Korčula respectively (two other
Croatian Adriatic islands). Both wrong seeds correctly failed to match
anything (there's no real `Korčula`-named record near the first point,
no real `Mljet`-named record near the second), and the admin-derived
fallback tier recovered real, villages-on-that-island names instead
(`Selca kod Starog Grada` on Hvar, `Smokvica` on Korčula) — which is
what actually exposed the mislabeling on inspection. Fixed by
correcting the two `SEED_NAMES` entries directly; the general lesson —
**a wrong seed fails safely into a lower-confidence tier rather than
silently asserting the wrong name** — is exactly why `name_source` is
tracked at all, and is left as a worked example in the script's own
`SEED_NAMES` comment.

A related, subtler bug also surfaced and was fixed: the tier-2
"unbounded" search match originally accepted any same-named record
within a fixed 0.3°-or-more pad of a landmass's own bounding box. That
pad was generous enough for Cyprus (correct — its administrative
centroid sits further from Natural Earth's own representative point
than a tight viewbox allows) but also wrongly matched the real
**Amorgos** landmass to **neighboring Astypalaia's** administrative
boundary (~0.3-0.4° away, inside a Cyclades cluster where neighboring
islands really are that close together). Tightened to a smaller floor
(0.12°) plus a size-proportional term, verified against both cases
directly (see the script's own comment at `wide_pad_x`/`wide_pad_y` for
the exact numbers) — Cyprus still resolves correctly, Amorgos and
Astypalaia no longer cross-match.

## Integration (hmsvc / widget)

`desk_hmsvc/natural-earth-map/service.py` was generalized to merge
`metadata.json` from **every** `Data/<x>/` directory it knows about
(currently `naturalEarth/` and this one), not just the first — so this
layer (`osm_island_names`, group "Named Islands," a small teal dot +
label, same shape as every other layer) shows up in the Natural Earth
Map widget's layer panel automatically, with **no widget-side code
change** beyond one generalization already worth making on its own: the
hover info line (`pop. 123,456` for a city) was hardcoded to one layer
id; it's now a generic `extraField`/`extraLabel` pair any layer's
`metadata.json` can declare (`area_km2`/`"km²"` here, `pop_max`/
`"population"` for cities) — see `natural-earth-map.ts`'s own
`LayerMeta` interface and `hitTest`.

## Re-running

```
python3 Data/OpenStreetMap-geocoding/fetch_island_names.py
```

Takes a few minutes — Nominatim's usage policy caps general use at 1
request/second, and this script respects that (a descriptive
`User-Agent` with a contact address is sent on every request, per that
same policy). Safe to re-run any time (e.g. after
`scripts/clip_natural_earth.py` regenerates the Natural Earth land
polygons with a different bbox) — it always starts from whatever's
currently in `Data/naturalEarth/`.

## Licensing and attribution

OpenStreetMap data is licensed under the **Open Database License
(ODbL) 1.0**. Unlike Natural Earth's public domain, ODbL attribution is
a real license term, not just a request — but what it actually requires
scales with *how much* of OSM's database you use. This project's own
prior research into this question (same question, asked directly before
this script was written) concluded: attribution is required for
real reuse, but the ODbL's share-alike clause specifically does **not**
apply to extracting a small number of individual facts — the
guidelines' own example is geocoding results — "as long as it does not
form a Derivative Database." This script extracts 37 island *names*
(not geometry, not any other OSM data), which is squarely that
"individual facts" case.

Credited anyway, matching this project's own established practice of
crediting a source even when not strictly required (see
`Data/naturalEarth/README.md`'s own "Recommended practice" section) —
every feature's geometry in `osm_island_names.geojson` still comes from
Natural Earth (public domain, already credited there); only the `name`
string and `osm_type`/`osm_id` properties are OpenStreetMap's own:

> © [OpenStreetMap](https://www.openstreetmap.org/copyright) contributors, [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/)
