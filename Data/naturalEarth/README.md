# Natural Earth data — Samothrace area

GeoJSON extracts from [Natural Earth](https://www.naturalearthdata.com)'s
10m-scale vector layers, clipped to a box roughly 1000 miles (N-S) by
1000 miles (E-W) centered on Samothrace, Greece, and stripped down to
only the attributes this project uses. Generated by
`scripts/fetch_natural_earth.py` + `scripts/clip_natural_earth.py` — run
the first to download and unzip the raw, full-world Shapefiles into
`.desk_temp/natural-earth-raw/` (not committed; ~90 MB), then the second
to produce the files in this directory (~1.3 MB total) from that raw
data. Re-running either script is safe: both skip work that's already
done (an existing download, an existing output directory).

## Bounding box

Computed in `scripts/natural_earth_common.py`: 500 miles north, south,
east, and west of Samothrace's centroid (40.4833°N, 25.5333°E), each
offset computed independently via the standard
miles-per-degree-of-latitude/longitude approximation (not a true
geodesic square — see that file's own docstring for why that's an
acceptable simplification at this radius). As of this writing that
resolves to approximately:

| | |
|---|---|
| Center | 40.4833°N, 25.5333°E |
| Latitude range | 33.25°N to 47.72°N |
| Longitude range | 16.02°E to 35.05°E |

Covering roughly: all of Greece, the Aegean and Ionian seas, Cyprus,
western/central Turkey, the Balkans, Romania, Moldova, southern Ukraine
and Crimea, and parts of Hungary, Italy (the "heel" and "boot"), and the
Black Sea.

## Files

| File | Natural Earth layer | What it has |
|---|---|---|
| `ne_10m_coastline.geojson` | `ne_10m_coastline` | Coastline, as lines. |
| `ne_10m_land.geojson` | `ne_10m_land` | Mainland + larger islands, as polygons. Confirmed Samothrace's own outline is in here (see "A real gap" below for what's *not* in here: its name). |
| `ne_10m_minor_islands.geojson` | `ne_10m_minor_islands` | Smaller islets `ne_10m_land` generalizes away (58 in this box), as polygons. |

| `ne_10m_populated_places.geojson` | `ne_10m_populated_places` | Cities, filtered to population ≥ 50,000 or a national/regional capital (219 in this box — Istanbul, Athens, Ankara, Thessaloniki, ... down to small regional capitals). |
| `ne_10m_geography_regions_polys.geojson` | `ne_10m_geography_regions_polys` | Named islands/island groups only (filtered from a much larger regions layer): Crete, Rhodes, Lesbos, Cyprus, Cyclades, Ionian Is., and Pelopónnisos (tagged "Island" by Natural Earth despite being a peninsula — kept as their own data, not corrected here). |
| `ne_10m_geography_marine_polys.geojson` | `ne_10m_geography_marine_polys` | Sea/strait/channel names (11 in this box): Mediterranean Sea, Aegean Sea, Black Sea, Adriatic Sea, Ionian Sea, Sea of Crete, Sea of Marmara, Sea of Azov, Tyrrhenian Sea, Bosporus, Dardanelles. Each feature's `properties` only carries the fields actually kept by
`clip_natural_earth.py` — every layer has ~25-170 attributes upstream
(multi-language name columns, per-country viewpoint columns, etc.);
see that script for the exact per-layer keep-list.

## Seas: a success, unlike islands

Asked directly: can the seas in this bbox be labeled the same way the
islands were? Unlike the island-name search below, **Natural Earth
answered this on the first try** — `ne_10m_geography_marine_polys` has
a real `name` field and real polygon coverage of this region, no
OpenStreetMap fallback needed.

Two things worth knowing if this layer is reused elsewhere:

- **Bbox pre-filtering alone isn't enough — a feature's raw bbox can
  lie.** A naive "does this feature's bounding box overlap my bbox"
  check keeps 12 candidates in this region, including "North Pacific
  Ocean" — its real geometry wraps the antimeridian, so its *bbox*
  spans the full -180°..180°, overlapping literally everywhere. Only
  after actually intersecting each candidate's real geometry against
  the bbox (which `clip_feature()` already did for every other layer
  in this pipeline) does it correctly clip to empty and drop out,
  leaving the 11 real matches. Worth remembering for any dataset with
  antimeridian-spanning features — this project's own
  `Data/naturalEarth/README.md`-documented bbox math never crosses
  ±180° itself, but a *source* feature's own geometry still can.
- **Seas nest, and that's real data, not a bug.** Mediterranean Sea's
  polygon fully contains Aegean Sea's, which contains Sea of Crete's —
  Natural Earth hands back every one of these as its own overlapping
  polygon+name, the same way a real atlas shows the broad name at
  small scale and the specific one once you zoom in. This script
  doesn't try to pick a "winner"; the widget's own label-declutter
  logic (skip a label that would overlap one already placed, biggest
  features processed — well, in this case, whichever order they're
  read in, not sorted by size, see its own code) decides what's
  actually legible at a given zoom.

This is also what motivated `process()`'s new `add_label_point` option
(used for this layer and, retroactively, for
`ne_10m_geography_regions_polys`): a label position computed as a
plain bounds-midpoint can land outside a concave or bbox-sliced
polygon entirely (on dry land, for a sea) — `add_label_point` instead
stores shapely's `representative_point()` (guaranteed inside the real
shape) as `label_lon`/`label_lat` properties, which the widget prefers
over its own bounds-midpoint fallback.

## A real gap: Natural Earth doesn't name Samothrace, or most Aegean islands

Two layers that look purpose-built for "island names" were tried and
dropped after inspecting the actual data:

- `ne_10m_minor_islands_label_points` has no `name` attribute at all in
  this release (only `featurecla`/`min_zoom`/`scalerank`) — despite
  being a "label points" layer.
- `ne_10m_geography_regions_points` (the point version of the layer
  used above) is a real named-point layer, but it's curated for
  notable/remote islands worldwide (Pacific atolls, sub-Antarctic
  islands, etc.) — it has **zero** features anywhere in this bounding
  box.

`ne_10m_geography_regions_polys` (what's actually used above) only
carries the short list of especially well-known islands/groups shown in
the table — not Samothrace, Lemnos, Thasos, Samos, Imbros/Gökçeada, or
most other individual Aegean islands. `ne_10m_populated_places` was
also checked directly for a "Samothraki" entry (the town sharing the
island's name) — it isn't there; too small a population for this
dataset.

**This isn't a "minor island" size-tier gap** — Samothrace (~178 km²) is
well above the size Natural Earth's own "minor islands" layer covers,
and is in fact part of `ne_10m_land` (the mainland-scale layer), not
`ne_10m_minor_islands`. So it's reasonable to wonder whether a
*political* layer — one step up from the purely physical layers above —
splits a country out by individual landmass and names each one. Checked
directly, using Samothrace plus three comparably-sized/notable
neighbors (Thasos, Lemnos, Imbros/Gökçeada) as a control group:

- `ne_10m_admin_0_countries` and `ne_10m_admin_0_map_subunits` (the
  latter specifically exists to split a sovereign state into separate
  records for disjoint territories — French Guiana as its own record
  from mainland France, for example) **both still return a single
  `NAME: "Greece"` record** covering all four test points — Greece's
  many islands are not split out as separate map-subunit records the
  way some countries' overseas territories are.
- `ne_10m_admin_1_states_provinces` (regional/state-level government
  units) returns a real, named region for each point — "East Macedonia
  and Thrace" for Samothrace and Thasos, "North Aegean" for Lemnos,
  "Çanakkale" for Imbros/Gökçeada — but that's the name of the
  *administrative region*, not the island. Several islands routinely
  share one region's name (as Samothrace and Thasos do here).

So the honest conclusion: Natural Earth, at this scale, simply has no
layer — physical or political — that names individual Aegean islands in
Samothrace's size class. The only per-island names available anywhere
in this data are the curated "famous enough to label on a small-scale
atlas" list in `ne_10m_geography_regions_polys` (Crete, Rhodes, Lesbos,
Cyprus, ...), which is closer to a notability cut than a size cut —
Lesbos made it, while Samothrace, Thasos, Lemnos, and Imbros/Gökçeada,
none obviously smaller or less real, did not. **If named small-island
labels are needed later, they'll have to come from a different,
non-Natural-Earth source** (e.g. OpenStreetMap), with its own separate
citation and license — don't expect a future re-run of this same
pipeline, against any Natural Earth layer, with a different filter to
find them; they're not in the source data at all.

**Follow-up, done:** `Data/OpenStreetMap-geocoding/` does exactly this
for every island in the region not much smaller than Samothrace itself
(~92 km²+) — see that directory's own README for the method, including
the direct finding that even Natural Earth's *political* layers
(`admin_0_countries`, `admin_0_map_subunits`, `admin_1_states_provinces`)
don't split Greece's islands out by name either, which is what actually
motivated going to OpenStreetMap in the first place.
